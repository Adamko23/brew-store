# Brew Store v0.1

## Product scope

Brew Store is a Rust/Iced 0.14 macOS desktop manager for Homebrew. The two
navigation destinations are Search and Installed. The initial public release is
v0.1.0, with a prebuilt Apple Silicon app and source for native Mac builds.

The interface follows native light/dark appearance, uses the system font and
cached SF Symbols masks, and supports English/Slovak in macOS preference order.
The beer-and-package icon is shared by the header, Dock and macOS bundle.
Interactive controls stay below the real AppKit titlebar; details occupy the
main content area with a back action. No inferred package categories are used.

## Behavior and invariants

- Homebrew is authoritative: installed info and outdated JSON own local state.
  A failed refresh preserves visible inventory but disables mutations.
- Search uses an abortable 180 ms debounce over a prepared shared index, runs
  matching/sorting off the UI thread, rejects stale generations and retains old
  rows until the new result is ready. Enter flushes pending work. No per-key Brew
  or network operation. At most 30 rows are constructed per page.
- Disabled packages are hidden from discovery but remain removable in inventory.
  Known cask minimum macOS requirements are explained and enforced.
- Local app icons and allocated installation sizes are inspected lazily with
  at most two inspections running at once and per-version caching. Unknown
  data remains unknown. No user documents are included in the size estimate.
- Open is offered only for a real declared installed .app. Its absolute path is
  revalidated before calling open -a with literal separate arguments.
- Formula/cask/tap identities remain separate. Runtime receipts include recursive
  entries: only declared_directly=true means a direct dependency. Unknown or
  ambiguous links are not guessed. No recorded Brew consumer proves nothing
  about software installed outside Brew.
- Mutations require confirmation, run serially and have bounded output logs.
  Failed exits retain their error and are reconciled with fresh state; an already
  applied version is explained without offering an unnecessary retry.
- Update All invokes one brew upgrade with normal metadata refresh, pin and
  self-updater policy. Preview can open during a refresh; execution waits for a
  verified inventory and revalidates the action.
- Formula uninstall verifies a unique installed token with the exact original
  typed/tap identity before using --formula TOKEN. This handles definitions that
  disappeared or migrated to casks without redirecting to the new package kind.
- Individual removals set HOMEBREW_NO_AUTOREMOVE=1 and verify record disappearance.
  The only --force exception is guarded cask record cleanup after all declared
  app paths are freshly verified absent. No --zap or direct user-data deletion.
- If current details fail, only the exact installed receipt may supply details;
  the UI explains that fallback and labels its recorded version honestly.
- Apple repair installs only a validated compatible stable CLT label from
  softwareupdate after confirmation and local authentication. Receipt checks
  determine success. Opening xcode-select's installer only means it was opened.
  No automatic macOS installation, restart, license acceptance or CLT deletion.
- No idle render timer or recurring tools scan. A running operation alone owns
  its progress timer. WGPU/Metal, prepared tokens and shared catalogue data avoid
  rebuilding expensive state on every UI event.

## Source boundaries

| Source | Responsibility |
| --- | --- |
| model.rs | Tolerant Homebrew JSON and identities |
| catalog.rs | Public catalogue and atomic public-only cache |
| brew.rs | CLI reads, guarded serialized mutations and process logs |
| assets.rs | Declared local bundles, icons, sizing and Open |
| dependencies.rs | Typed installed dependency graph |
| search.rs | Prepared catalogue search |
| tools.rs | Apple CLT diagnosis and supported repair paths |
| native.rs / i18n.rs | Dock icon and native locale preferences |
| app.rs / ui/ | Asynchronous state, reconciliation and presentation |

## Verification and release

The behavioral suite covers JSON shapes, identities, dependency receipts, search
races, cache behavior, command arguments, serialization, bounded logs, guarded
removal, failed-operation reconciliation, declared app opening, localization and
Apple repair. Mutation and launch tests use fake executables.

For each release, run formatting, the full test suite and strict Clippy, then
build the release app. Verify code signing, bundle version and architecture, DMG
integrity, ZIP extraction and checksums. Test the extracted app on a native Mac.
Published artifacts are ad-hoc signed until Developer ID signing/notarization is
configured; documentation must disclose that limitation.

Public repository files exclude local caches, installed inventories, logs,
credential helpers and machine-specific repair history. Build artifacts are
published as versioned release assets rather than committed to Git.
